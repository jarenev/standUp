# StandUp — апгрейд скинов Standoff 2

Игровая площадка в стиле standoffcraft: апгрейд скинов, магазин, продажа, вывод скинов, промокоды,
пополнение по QR-коду и секретная админ-панель.

## Возможности

- **Апгрейд** — вертикальная шкала с делениями, стрелка раскачивается и плавно затухает.
  Зелёная зона = победа (в ней написан % удачи), красная = проигрыш (в ней % неудачи).
- **Настройки апгрейда** — слайдер шанса (1–90%), быстрые пресеты иксов (x1.5 … x50),
  режим «апгрейд до скина» и скорость анимации (быстро / медленно).
- **Ставка** — голда с баланса и/или скин из инвентаря (можно комбинировать).
- **Магазин** — расположен ниже анимации, 70+ скинов Standoff 2 с примерными рыночными ценами.
- **Продажа предметов** — 90% от рыночной цены сразу на баланс.
- **Пополнение от 50 G** — создаётся платёж, открывается страница только с QR-кодом
  (сверху надпись `Сумма: ** G ; Код: номер пополнения`). QR ведёт на `/pay/<код>`, где
  показывается «Успешно» с галочкой и баланс зачисляется. Как только платёж прошёл — QR пропадает
  и игрока перекидывает в профиль.
- **Мои скины** (в профиле) — предупреждение, что аватарка на сайте должна совпадать с аватаркой
  в игре, и инструкция по выводу: выставить `M4 "FLOCK"` на сумму с учётом комиссии 20%
  (вывод 100 G → выставить 125.00 G).
- **Промокоды** — активируются в профиле.
- **Админ-панель** `/admin` — доступна аккаунту с логином **JARENEV** (для всех остальных — 404):
  - переключатель «Подкрутка» — все апгрейды всех игроков ждут решения админа
    (видно ник, аватар, сумму ставки, икс, шанс, потенциальную выплату) → Победа / Проигрыш / Возврат;
  - выводы: аватар игрока (можно скачать в оригинале), название скина, сумма выставления и чистая сумма;
  - купоны: `Купон: НАЗВАНИЕ; Сколько даёт: сумма; Кол-во активаций`;
  - игроки и ручная корректировка баланса.

## Локальный запуск

```bash
npm install
cp .env.example .env
# В .env укажите DATABASE_URL и AUTH_SECRET
npx drizzle-kit push
npm run dev
```

Первый аккаунт с логином `JARENEV` автоматически становится админом.

## GitHub → Neon → Vercel

### 1. Отправьте проект в GitHub

Создайте на GitHub пустой репозиторий **standup** без README и выполните в папке проекта:

```bash
git init
git add .
git commit -m "Initial StandUp release"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/standup.git
git push -u origin main
```

Файл `.env` защищён через `.gitignore` и не попадёт в репозиторий.

### 2. Создайте базу Neon

1. Откройте https://console.neon.tech и создайте проект.
2. В окне **Connect** выберите ветку `main`, базу `neondb` и включите **Pooled connection**.
3. Скопируйте строку вида `postgresql://USER:PASSWORD@HOST-pooler.REGION.aws.neon.tech/neondb?sslmode=require`.
4. Локально замените `DATABASE_URL` в `.env` на эту строку и задайте `AUTH_SECRET`.
5. Создайте таблицы:

```bash
npx drizzle-kit push
```

Каталог скинов заполняется автоматически при первом открытии сайта.

### 3. Разверните на Vercel

1. Откройте https://vercel.com/new, подключите GitHub и импортируйте репозиторий `standup`.
2. Framework Preset оставьте **Next.js**, Root Directory — `./`, Build Command — стандартный.
3. В **Environment Variables** добавьте для Production, Preview и Development:
   - `DATABASE_URL` — pooled connection string из Neon;
   - `AUTH_SECRET` — длинная случайная строка (например, вывод `openssl rand -base64 48`);
   - `ADMIN_PASSWORD` — отдельный сложный пароль для регистрации и входа `JARENEV`.
4. Нажмите **Deploy**.
5. После деплоя проверьте `https://ВАШ-ДОМЕН.vercel.app/api/health`: ожидается `{ "ok": true }`.
6. Зарегистрируйте аккаунт с логином `JARENEV`, используя точное значение `ADMIN_PASSWORD`. Без этого секрета зарезервированный админ-логин зарегистрировать нельзя.

Каждый `git push` в ветку `main` автоматически создаёт новый production deployment на Vercel.
